v1.3.10 更新（修正温度振荡，α 换成本机日志拟合值）

这是给你那台 K90U 的具体修复。上一版的默认值本身没问题，
是你机器上的配置被改成了 kd=15 / tdot_tau_s=12 / max_ma=9000，
这三个组合起来会让温度大起大落。

一、为什么波动这么大（实测数据）

用 24 小时充电日志（28,721 条）反推了本机热参数并算了环路相位裕度：

  配置                   相位裕度(I=5/8/11A)   闭环仿真峰值
  kd=15 tdot_tau_s=12     25° / 20° / 17°       45.1℃（越过 hard_temp）
  kd=40 tdot_tau_s=6      47° / 42° / 36°       42.8℃

（峰值那一列是无噪声理想仿真，不是真机实测，只用来量化相位裕度的影响；
实际振荡幅度以上面的真机日志为准。）

相位裕度低于 30° 就会持续振荡。实测振荡周期 273 秒（4.5 分钟），
温度在 36.5~43.9℃ 之间摆，功率 22~50W。

另外 max_ma=9000 让控制器失去调节余量：稳住 43℃ 需要约 8350mA，
只剩 8% 空间，36% 的时间顶部被顶死，环境一热就守不住。

二、迁移（cfg_version 5 -> 6）

只改还停在旧值上的项，手动调过的一律保留（按数值比较，15.0 / 1.5e1 与 15 等价；
缺尾换行、重复键、行尾注释的旧配置也能正确迁移，重复键以最后一处为准；
读配置的辅助脚本语义已与守护进程统一）：

  kd            15   -> 40      （阻尼不足会振荡到硬停）
  tdot_tau_s    12   -> 6.0     （微分滞后同样吃相位裕度）
  max_ma        9000 -> 15000   （留出调节余量，约 65W，仍低于原厂 17600）
  pred_alpha    0.06 -> 0.07    （见下）

三、α 从 0.06 改成 0.07

0.06 是"17A 约 +17K"反推的出厂估值。0.07 是本机三份独立拟合的中位数：
测试集 0.0584、留一会话验证 0.0753、24 小时全量 0.0793。
影响温和：开始收力的温度从 39.2℃ 提前到 38.3℃，冷段功率无损。

τ 保持 300s 没有跟着改：三份拟合给出的 τ 是 91~155（标准差约 30%），
基本测不准。而 τ 是前瞻时域 H=60s 的分母，取小会让预测层在 30℃ 就开始
压流（实测 τ=115 时 30.6℃ 介入，冷段功率从 20A 砍到 13.7A），
与"冷段不压"的设计意图冲突。

四、值得记下来的一件事：闭环数据辨识不出 α

尝试过三种在线辨识方案，全部失败，写在这里免得以后再走一遍：

  a) 三参数联合最小二乘    α 随时间段变 4 倍（0.018~0.079），条件数 1e-6
  b) 固定 τ 只解 α          α 随假定 τ 线性变 7 倍（τ=60→0.022，τ=300→0.163）
  c) 只解 k=α/τ             解出负值，等于"电流越大温度越低"，物理上不可能

根因是闭环本身：控制器把温度钉在目标上，同一电流档（5.5A）下的温度
跨度有 22℃，真正能定 α 的准稳态点在整份日志里只有 2 个且几乎重合。
想要真正的本机 α，只能跑 tools/identify-thermal.sh 的开环阶跃。

五、WebUI 与"一键恢复默认"

- 配置页底部新增「恢复默认配置」按钮：二次确认后一次性写盘并热重载。
- 底层新增子命令：thermocharge defaults [--apply]
    只打印：thermocharge defaults
    恢复：  thermocharge defaults --apply
  默认值只有一个来源——先调 cfg_defaults() 再按字段偏移读，
  WebUI 和代码里的默认值不会对不上。
- 注意：恢复会覆盖所有项，包括本页不显示的 pred_alpha / pred_tau_s。
  用 identify-thermal.sh 辨识过本机 α 的，恢复后要重新填回。
- 顺手修了写配置时把 0600 权限写成 0644 的旧问题（rename 换了 inode）。
- demo 默认 pred_alpha 同步为 0.07。

六、新增：状态页「状态说明」卡 + 一处回读路径修复

状态页「限流」卡片下面新增说明卡：

- 状态机 15 个取值逐个有中文解释（idle / grace / regulate / regulate_max /
  regulate_min / windup / predict / predict_hit / soft_land / soc_release /
  hard_safety / hard_pause / sensor_fault / ctl_fault / hold），附「全部状态含义」
  折叠列表。
- 按当前读数自动诊断：比如 regulate_max 但温度远低于目标时，解析 ichg_limit
  回读，若赢家不是模块的 tag，会直接写明「限流来自系统：<tag> <type> <mA>」，
  并解释 Min 聚合只能往下压。另有：温度压不下来、目标温度≥48℃、硬上限离目标
  太近、wired_chg_curr 回读为空、守护进程未运行/模块停用/dry_run 等提示。

顺带修复：WebUI 读回 wired_chg_curr 的路径写错了（charge_interface/），
本机没这个节点，所以一直显示「—」；守护进程写的是 charger_thermal/。

七、修复：开环辨识脚本没限住电流

2026-11-17 23:18 那次辨识请求 6A，手机实测 66.75W / 4.429V ≈ 15.07A：
脚本只投了 charge_interface/ichg_limit，而电荷泵阶段这个投票不约束实际
电流，真正起作用的是 charger_thermal/wired_chg_curr（单位 µA）。
守护进程平时靠 ctl_mode=2 双写，脚本冻结它之后只接了一半。

现在脚本按配置的 ctl_mode 同样双写，并在采样循环里每 5 秒重投一次
（系统会周期覆写 wired_chg_curr）。另外：

- 接管前检查节点可写（不充电时 wired_chg_curr 是只读的），不可写直接退出；
- 第一档 60 秒时核对实测电流，低于 3A 或高于 9A 都立即 [ABORT]，
  不再跑满 9 分钟才在拟合阶段发现数据作废。
